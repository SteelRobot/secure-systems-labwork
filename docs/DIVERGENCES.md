# Журнал расхождений с ЛР №2

| № | Что изменено | Причина |
|---|--------------|---------|
| 1 | Регистрации нет; пользователи создаются сидом (`api/app/seed.py`) | В ЛР №2 нет эндпоинта регистрации; учётные записи университетские |
| 2 | `POST /api/applications` создаёт заявку в статусе `draft`; добавлен `PATCH /api/applications/{id}/submit` (`draft` -> `submitted`); параметр `document_ids` убран из POST | Документ привязан к существующей заявке (`documents.application_id NOT NULL`), загрузка идёт на `/applications/{id}/documents` |
| 3 | Подразделение заявки определяется через `users.department_id` заявителя (JOIN), колонка в `applications` не добавлена | Схема из ЛР №2 сохранена без изменений |
| 4 | Добавлены эндпоинты: `POST /api/auth/password-reset/confirm`, `POST /api/auth/logout`, `GET /api/completeness-checks/{id}`, `GET /api/reports/{id}`, `GET /api/reports/{id}/download`, `GET /api/health` | Без них сценарии из ЛР №2 (сброс пароля, выход, получение результата ИИ-проверки, скачивание отчёта) не завершаются |
| 5 | TLS только на внешней границе (nginx, самоподписанный сертификат). Внутри docker-сети (SQL, Redis, AMQP, S3, HTTP к заглушкам) без TLS | Сеть изолирована, локальное развёртывание; доступ к БД/Redis/брокеру не публикуется наружу |
| 6 | Политика токенов (в ЛР №2 отсутствовала): JWT HS256, 30 мин, `sessionStorage`, сессия по `jti` в Redis | Нужна для logout и отзыва |
| 7 | Тестовые данные создаёт `api/app/seed.py`, а не `db/seed.sql` | Пароли должны быть захешированы Argon2id с перцем, это делает код приложения |
| 8 | Модель (LLM): эндпоинты `completeness-check` – асинхронная задача в `worker` с выгрузкой в `llm_checks`, контейнера модели нет | Разрешено методичкой ЛР №3 |
| 9 | Финансовое подразделение и мониторинг – контейнер `external-stubs`; почта – Mailpit | Коммерческие/внешние системы заменены заглушками с проверкой API-токена |
| 10 | Добавлены `db/roles.sql` (роли `app_api`, `app_worker`) | Требование ЛР №3, п. 2.2; в ЛР №2 были описаны только на уровне идеи |
| 11 | Объектное хранилище – RustFS (S3 API) вместо MinIO; одна пара ключей приложения вместо отдельной политики на бакет | Образы MinIO недоступны в публичных реестрах; протокол S3 API сохранён |
| 12 | Из `applications` удалены `payment_status`, `payment_reference` и их ограничение/индекс; из `chk_applications_status` убрано значение `paid` | Система не выплачивает средства: она принимает и обрабатывает заявки, а финансовому подразделению передаёт только сводный отчёт. В ЛР №2 (D2, вывод 3) выплата была ошибочно включена в систему |
| 13 | Очередь `payments` (и `payments.dlq`) не создаётся; финансовому подразделению уходит уведомление со ссылкой на отчёт (`POST /finance/reports`), а не платёж | То же: передача сведений (B-11) – это сводный отчёт, формируемый через очередь `reports` |
| 14 | Роль `app_worker` не имеет права `UPDATE` на `applications` | Платёжных полей больше нет, worker заявки только читает |
| 15 | Унификация ролей: `applicant` (заявитель), `employee` (ответственный сотрудник подразделения), `technical_admin` (техспециалист) | Студенты и сотрудники университета едины в роли заявителя; роль `service_admin` переименована в `employee` для наглядности |
| 16 | Ответственному сотруднику недоступны чужие черновики (`status = 'draft'`) как в списке, так и по прямому UUID | Защита приватности: пока заявка не отправлена, сотрудник не должен видеть черновики заявителя |

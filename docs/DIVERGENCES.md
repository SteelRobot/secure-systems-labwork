# Журнал расхождений с ЛР №2

| № | Что изменено | Причина |
|---|--------------|---------|
| 1 | `POST /api/applications` создаёт заявку в статусе `draft`; добавлен `PATCH /api/applications/{id}/submit` (`draft`/`needs_revision` -> `submitted`); параметр `document_ids` убран из POST | Документ привязан к существующей заявке (`documents.application_id NOT NULL`), загрузка идёт на `/applications/{id}/documents` |
| 2 | Подразделение заявки определяется через `users.department_id` заявителя (JOIN), колонка в `applications` не добавлена | Схема из ЛР №2 сохранена без изменений |
| 3 | Добавлены эндпоинты: `POST /api/auth/password-reset/confirm`, `POST /api/auth/logout`, `GET /api/completeness-checks/{id}`, `GET /api/reports/{id}`, `GET /api/reports/{id}/download`, `GET /api/health` | Без них сценарии из ЛР №2 (сброс пароля, выход, получение результата ИИ-проверки, скачивание отчёта) не завершаются |
| 4 | TLS только на внешней границе (nginx, самоподписанный сертификат). Внутри docker-сети (SQL, Redis, AMQP, S3, HTTP к заглушкам) без TLS | Сеть изолирована, локальное развёртывание; доступ к БД/Redis/брокеру не публикуется наружу |
| 5 | Политика токенов (в ЛР №2 отсутствовала): JWT HS256, 30 мин, `sessionStorage`, сессия по `jti` в Redis | Нужна для logout и отзыва |
| 6 | Тестовые данные создаёт `api/app/seed.py`, а не `db/seed.sql` | Пароли должны быть захешированы Argon2id с перцем, это делает код приложения |
| 7 | Финансовое подразделение и мониторинг – контейнер `external-stubs`; почта – Mailpit | Коммерческие/внешние системы заменены заглушками с проверкой API-токена |
| 8 | Объектное хранилище – RustFS (S3 API) вместо MinIO | Образы MinIO недоступны в публичных реестрах; протокол S3 API сохранён |
| 9 | Из `applications` удалены `payment_status`, `payment_reference` и их ограничение/индекс; из `chk_applications_status` убрано значение `paid` | Система не выплачивает средства: она принимает и обрабатывает заявки, а финансовому подразделению передаёт только сводный отчёт. В ЛР №2 (D2, вывод 3) выплата была ошибочно включена в систему |
| 10 | Очередь `payments` (и `payments.dlq`) не создаётся; финансовому подразделению уходит уведомление со ссылкой на отчёт (`POST /finance/reports`), а не платёж | То же: передача сведений (B-11) – это сводный отчёт, формируемый через очередь `reports` |
| 11 | Роль `app_worker` не имеет права `UPDATE` на `applications` | Платёжных полей больше нет, worker заявки только читает |

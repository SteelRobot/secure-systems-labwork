# Назначение файлов каркаса

## Корень

| Файл | Назначение |
|---|---|
| `docker-compose.yml` | Описывает все контейнеры (db, redis, broker, storage, mail, external-stubs, api, worker, web и одноразовые db-seed, storage-init), две сети (`front`: web↔api, `data`: всё остальное), тома и порядок запуска. Секреты берёт из `.env`. |
| `.env.example` | Список всех переменных окружения с комментариями, без значений. Шаблон для `.env`. |
| `.env` | Реальные секреты. Создаётся скриптом, в git не попадает (в `.gitignore`). |
| `.gitignore` | Исключает `.env`, служебные файлы Emacs/LaTeX, `__pycache__`, `node_modules`, `web/dist`. |
| `README.md` | Запуск и остановка, адреса сервисов, тестовые учётные записи, сброс базы. |
| `scripts/init-env.sh` | Генерирует `.env` из `.env.example` со случайными паролями, ключом JWT и перцем. Существующий `.env` не перезаписывает. |

## `db/` — база данных

| Файл | Назначение |
|---|---|
| `schema.sql` | Схема из ЛР №2 с изменениями (убраны платёжные поля, см. `DIVERGENCES.md`, п. 12). Postgres выполняет её при первом запуске на пустом томе. |
| `roles.sql` | Создаёт роли `app_api` и `app_worker` и выдаёт им минимальные права через GRANT. DDL им запрещён. |
| `init-roles.sh` | Обёртка: передаёт пароли ролей из окружения в `roles.sql` как переменные psql. Запускается при инициализации БД. |

## `api/` — основной сервис (FastAPI)

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ на Python 3.12, запуск от непривилегированного пользователя. Тот же образ используют `db-seed` и `storage-init`. |
| `requirements.txt` | Зависимости: FastAPI, psycopg, redis, pika, minio (S3-клиент), argon2-cffi, pyjwt. |
| `.dockerignore` | Исключает кэш Python из образа. |
| `app/__init__.py` | Пустой, делает каталог пакетом. |
| `app/main.py` | Точка входа: создание приложения, пул БД при старте, обработчик непредвиденных ошибок (клиенту 500 без деталей, подробности в лог), `GET /api/health`. Сюда будут подключаться маршруты. |
| `app/config.py` | Читает настройки из окружения. Значений по умолчанию для секретов нет, без переменной сервис не стартует. |
| `app/db.py` | Пул соединений PostgreSQL под ролью `app_api`. |
| `app/cache.py` | Клиент Redis: сессии, лимиты частоты, идемпотентность, коды сброса пароля. |
| `app/broker.py` | Функция `publish(queue, message)`: отправка сообщения в RabbitMQ. |
| `app/storage.py` | Клиент объектного хранилища (S3 API). |
| `app/storage_init.py` | Одноразово создаёт бакет `documents`. Запускается контейнером `storage-init`. |
| `app/security.py` | Хеширование пароля: HMAC с перцем, затем Argon2id с индивидуальной солью. Проверка пароля. |
| `app/seed.py` | Тестовые данные: 2 подразделения, 6 пользователей (по одному на роль, 2 студента, 2 сотрудника подразделений), 4 заявки. Запускается контейнером `db-seed` под суперпользователем БД. |

## `worker/` — фоновый обработчик

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ на Python 3.12, запуск от непривилегированного пользователя. |
| `requirements.txt` | Зависимости: psycopg, pika, redis, minio, httpx. |
| `.dockerignore` | Исключает кэш Python из образа. |
| `worker/__init__.py` | Пустой, делает каталог пакетом. |
| `worker/main.py` | Слушает очереди `audit`, `notifications`, `reports`. Пока только логирует сообщение и подтверждает его. Реальные обработчики отмечены TODO. |

## `web/` — клиент (React + nginx)

| Файл | Назначение |
|---|---|
| `Dockerfile` | Двухэтапная сборка: Node собирает SPA, nginx раздаёт результат. Тут же генерируется самоподписанный сертификат. |
| `nginx.conf` | HTTPS на 443, редирект с 80, заголовки безопасности, проксирование `/api/` в контейнер `api`, лимит размера тела запроса. |
| `.dockerignore` | Исключает `node_modules` и `dist` из контекста сборки. |
| `package.json` | Зависимости и скрипты сборки (React, Vite, TypeScript). |
| `tsconfig.json` | Настройки TypeScript. |
| `vite.config.ts` | Настройки Vite, проксирование `/api` при локальной разработке. |
| `index.html` | HTML-страница, в которую монтируется приложение. |
| `src/main.tsx` | Точка входа React. |
| `src/App.tsx` | Заглушка интерфейса: заголовок и статус API. Экраны будут добавляться вместе с эндпоинтами. |

## `rabbitmq/` — брокер

| Файл | Назначение |
|---|---|
| `definitions.template.json` | Описание очередей (`audit`, `notifications`, `reports`) с лимитом повторных доставок, очередей недоставленных сообщений (`*.dlq`), обменников и пользователя приложения с минимальными правами. Пароль подставляется при старте. |
| `rabbitmq.conf` | Указывает RabbitMQ загрузить определения при старте. |
| `entrypoint.sh` | Подставляет имя пользователя и пароль из окружения в шаблон определений и запускает RabbitMQ. |

## `external-stubs/` — заглушки внешних систем

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ на Python 3.12 для заглушки. |
| `main.py` | Имитирует финансовое подразделение (`POST /finance/reports`: уведомление о готовом отчёте со ссылкой) и систему мониторинга (`POST /metrics`). Проверяет API-токен и отвечает 401 без него. Повтор с тем же `report_id` не создаёт дубликат. |

## `docs/` и `requests/`

| Файл | Назначение |
|---|---|
| `docs/DIVERGENCES.md` | Журнал расхождений с ЛР №2 (16 пунктов). Нужен на первой странице отчёта. |
| `docs/FILES.md` | Этот файл. |
| `requests/README.md` | Заглушка для будущей коллекции запросов (curl-скрипты по эндпоинтам). |
